# Martin Luk 强势回调（本地适配）

策略 ID：`martin-luk-pullback-v1`。这是面向加密市场的 Rust 本地规则策略，使用 **4h 判断强势趋势、15m 等待首次回调并确认入场**，默认只做多。策略管理会显示参数，新增策略默认不自动启用。

它参考 Martin Luk 公开介绍的强势标的、上升 EMA 附近首次回调、AVWAP 支撑与紧止损原则。原作者的方法包含主观判断并持续调整；本地的周期、峰值定位、支撑重合、确认方式和退出阈值是工程化定义，不是原版策略的精确复制。本次实现不宣称回测收益或胜率。

## 参考原则与本地规则

| 主题 | 公开原则 | 本地量化适配 |
| --- | --- | --- |
| 标的 | 关注有动能、波幅充足的强势标的 | 4h EMA 多头排列、观察期涨幅、每 6 根 4h 合成的 24h 平均波幅 |
| 回调 | 关注上升 EMA 附近的首次回调，结合 AVWAP | 从已确认的 4h 波段峰值固定锚点，机械识别首次支撑回调 |
| 执行 | 较大周期定位，较小周期确认，靠近失效位置入场 | 4h 筛选与支撑，15m 收盘确认；用 15m ATR 限制追价和止损 |
| 风险 | 较新的本人问答提到单笔约 0.5% 账户风险、单股仓位不超过 35% | 默认风险预算 0.5%，包括共享成本模型；单笔名义仓位最多为权益 35% |
| 退出 | 多头使用过 9EMA 跟随；公开做空问答中的分批退出包含主观判断 | 默认 15m EMA9 收盘失守退出，远端 10R 目标，最长 48h；固定分批默认关闭 |

35% 在这里约束的是名义仓位，不是保证金；开杠杆不能放大这个上限。0.5% 是按计划价格和共享成本计算的风险预算，实际跳空、滑点或交易所执行差异仍可能使损失超过预算。

## 信号规则

1. **只读取已收盘行情。** 4h 与 15m 各需 240 根行情窗口；主扫描和历史回放仍使用现有 1m 调度。新信号最早在后续计划周期执行，不回填到信号 K 线。挂单最长存续 45 分钟，错过确认后的入场窗口即过期；在线与回放均复用挂单失效宽限和取消逻辑。
2. **先确认强势趋势。** 4h EMA 默认 9、21、50，要求快速 EMA > 中速 EMA > 慢速 EMA；快速与中速 EMA 均高于前一根的值，4h 收盘不低于中速 EMA，不要求慢速 EMA 也上升。最近 30 根 4h 的涨幅至少 10%。这是单币种自身动量过滤，不包含股票行业、题材强弱或全市场相对强弱排名。
3. **检查波幅。** 每连续 6 根 4h 作为一组 24h 波幅，最近 14 组取均值，默认至少 5%。该口径与股票市场的日历交易日 ADR 不同，不能把参数直接当作同一统计量。
4. **固定本波段峰值与 AVWAP。** 峰值是最近 12 根已收盘 4h 中的最高 `high`。从该峰值 4h 的 `openTime` 起，将 15m 典型价 `(high + low + close) / 3` 按成交量累计加权。回调计数从该 4h 收盘之后开始；锚点固定于峰值 4h 的开盘时间，不假装知道该 4h 内最高价的精确发生时间，也不使用未来 K 线寻找峰值。
5. **只接受首次回调。** 对峰值 4h 收盘后的每根 15m，使用该时点已经收盘的 4h EMA 与当时累计的 AVWAP 判断支撑接触。连续接触记作一个回调段；离开后再次接触记作第二段，只允许累计恰好一段，且最后一次接触必须在当前或前一根 15m。峰值 4h 收盘后默认最多等待 128 根 15m，即 32 小时。新高对应新的波段观察。
6. **要求支撑重合与 15m 转强确认。** 同一根 15m 的高低区间须在 0.35 ATR 容差内接触快速 EMA、中速 EMA、固定 AVWAP 三项中的至少两项；所选支撑线之间最大距离不得超过两倍容差，避免一根大幅波动 K 线横跨远离的支撑被误判为重合。以最近一次接触中的最高支撑为确认位置：回调最低价允许下探不超过 0.75 ATR；当前 15m 必须阳线收盘、收盘严格超过前一根最高价，且不低于该支撑和 15m 快速 EMA；收盘高于支撑不得超过 1 ATR。所有这些 ATR 均在 15m 计算。触及均线本身不足以产生买入信号。
7. **初始止损必须足够近且有效。** 先在回调低点外增加 0.15 ATR 止损缓冲；距离不足最小止损比例 0.3% 时，向外放宽保护位置。以计划入场区间上沿检查最终价格风险，不得超过 3.5%，同时不得超过 24h 分组平均波幅的一半。不会为通过上限而把结构止损向内压缩。净收益风险比至少 2；条件不成立时保持观望。
8. **持仓采用一致的退出规则。** EMA 退出周期与最小持仓根数冻结在订单初始计划的 `martinLukExit` 中。初始硬止损始终有效；至少持仓 1 根 15m 后，收盘失守 EMA9 即退出。远端获利目标默认 10R，最长 192 根 15m（48 小时），任一出场条件先满足即处理。默认不继承通用均线止盈或主观分批；可显式开启固定 3R、5R 各减初始仓位 15% 的选项。启用分批时，两档 R 必须递增且第二档低于远端目标。

“首次回调”由上述机械过程近似，无法还原原作者在图表中对整理结构、板块、交易环境和执行细节的全部主观判断。重新选择一个更近的波段峰值会产生新的观察区间，因此它也不是一只标的终生只允许交易一次。

## 仓位与共享风控

默认账户权益风险比例为 `riskPerTrade = 0.005`，执行杠杆限制为 1 倍。仓位由可用权益、初始止损距离，以及共享手续费、滑点和持仓资金费模型共同约束；再取 `maxNotionalPct = 0.35` 的名义仓位上限。两项均由共享订单提交路径校验，自动化评分仓位、杠杆和最小下单规模不能把实际提交的计划扩大到这些约束之外。若受交易所或系统最小规模限制，无法满足上限，则跳过订单。

本策略默认最多同时存在 5 个挂单或持仓。账户资金、同币种冲突、置信度门槛、流动性筛选、冷却和全局开仓限制继续由已有公共模块处理，因此满足形态不等于一定成交。不会为了得到成交而自动关闭这些约束。

参数中的比例使用小数：`0.10 = 10%`、`0.05 = 5%`、`0.005 = 0.5%`。1R 是初始价格风险单位，不是账户权益的 1%。

## 本地使用

在“策略管理”找到 **Martin Luk 强势回调（本地适配）**，展开查看规则参数并保存。历史回测可以在未启用自动扫描时进行；保存参数不会自动启用新策略，也不会替换已有订单的参数快照。确认参数和研究结果后，可使用已有策略开关加入自动扫描。

现有普通“本地分析 / 本地多周期分析”入口有自己的分析逻辑，不按此策略 ID 执行。此策略接入的是注册策略扫描和现有 Rust 研究回测。

读取配置：`GET /api/strategies/martin-luk-pullback-v1`。保存参数且保持未启用，可向 `PUT /api/strategies/martin-luk-pullback-v1` 发送：

```json
{
  "enabled": false,
  "params": {
    "riskPerTrade": 0.005,
    "maxNotionalPct": 0.35,
    "partialTpEnabled": false
  }
}
```

先通过 `POST /api/research/indicator-history/fetch` 补本地历史；请求示例中的日期可替换为已过去、跨度不超过 31 天的区间：

```json
{
  "symbol": "BTCUSDT",
  "strategyId": "martin-luk-pullback-v1",
  "startTime": "2026-10-01T00:00:00Z",
  "endTime": "2026-10-10T00:00:00Z"
}
```

补历史接口根据注册信息准备 1m、4h、15m 及各周期预热数据。检查条数、断档和错误后，向 `POST /api/research/backtest` 发送：

```json
{
  "symbol": "BTCUSDT",
  "strategyId": "martin-luk-pullback-v1",
  "startTime": "2026-10-01T00:00:00Z",
  "endTime": "2026-10-10T00:00:00Z",
  "initialBalance": 10000,
  "validationFraction": 0.3,
  "params": {
    "riskPerTrade": 0.005,
    "maxNotionalPct": 0.35,
    "partialTpEnabled": false
  },
  "grid": {
    "supportToleranceAtr": [0.25, 0.35],
    "maxChaseAtr": [0.75, 1]
  }
}
```

接口仅运行研究，不保存参数或启用策略。训练与验证按时间拆分，参数组合只按训练区间排序。检查成交数量、净收益、回撤、活动订单、断档与拦截原因；少量交易或零交易不代表策略已被验证。该 API 是单币种回放，不包含全市场候选竞争；期末未平仓按共享引擎浮盈计入权益，不强制平仓。执行、成本、风控与出场复用现有 Rust 共享模块。

策略复核触发的 EMA 退出沿用现有主动平仓接口，目前在线记录和回测的标准原因码均为 `manual`；该标签不代表用户点击了手动平仓。形态判断本身返回 `CLOSE`，专项测试会核对 EMA 退出的具体时间、成交价与费用。

## 实现验证（2026-10-17）

已通过 `cargo fmt --check`、`cargo check --all-targets`、`cargo test --all-targets`，以及显式运行的隔离 PostgreSQL/HTTP 契约测试 `cargo test --test backend-integration -- --ignored --nocapture`。Windows 构建使用 `CARGO_BUILD_JOBS=1` 控制内存占用。

新增 14 项策略测试与 8 项共享风险测试，覆盖首次回调、重复回调拒绝、未来数据隔离、完整辅助窗口、45 分钟挂单过期、冻结 EMA 出场、成交成本与真实报价数量风险预算。合成历史还通过现有 `backtest::replay` 完成开仓、后续成交与 EMA 退出；这些结果验证功能和因果性，没有评估真实历史收益。
