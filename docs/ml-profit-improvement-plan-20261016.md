# 下一轮盈利改进方案

本轮已完成现有回放的只读亏损归因，结果见[亏损诊断](../reports/ml-profit-diagnosis-20261016.md)。用户授权开始训练后，已实现多空净收益回归、每周重拟合、独立样本外校准和门槛验证、共享资金账户小时回放，运行与阶段说明见[净收益模型训练](ml-profit-training.md)。目标是新数据上的扣成本净收益和共享账户风险；分类准确率作为诊断指标。新候选仍需前向验证，Demo 模型保持不变；小时归档尚不能重建即时撮合和分钟扫描。

## 已有证据

- 180 天、873 个合约的上一轮已完成；最后历史保留段的 Chronos + LightGBM 净收益合计为 -536.18 USDT，去掉 Chronos 的对照为 -472.07 USDT。二者均未达到部署条件。
- 当前训练及早停目标是三分类对数损失。同一方向的小额盈利与大额盈利会被压成相同类别，因此分类概率不等于该方向的胜率或预期净收益。
- 最终窗口训练区间截至 2026-08-11 UTC，最终历史检验区间为 09-24 至 10-14 UTC。该长期冻结协议与定期更新模型的实际使用方式不同；需要独立对照验证更新频率的影响。
- 三个窗口的 Chronos 校准均选择 `median_shrink=0`，仍可保留区间宽度信息。这轮没有证明 Chronos 中位价格方向具有增量交易价值。
- 目前按原始验证概率选择候选，然后在独立校准集拟合温度，但确认阶段仍使用同一固定概率门槛。校准改变概率尺度，下一轮需明确区分模型验证、概率校准和开仓门槛验证。
- 当前回放采用每币独立 1,000 USDT 账户；收益合计和最大单币回撤不代表 Demo 共享资金池表现。

这些证据支持改变实验重点，尚不能证明任何新设置必然盈利。

## 1. 亏损归因与执行一致性

使用 Rust `nofx-ml-diagnose` 逐个读取已保存的回放，核对订单、信号、成本与原报告，再按多空、退出原因、入场概率、币种和 UTC 日期分组。输出包含源文件哈希，并标记 `post_hoc` 和 `descriptive_only`。

分析使用最终闭合订单的累计 gross/net，分批退出不重复计算。滑点已经计入成交价；净收益对账为 `gross - fees - funding + isolatedLossAdjustment`，不能再扣一次滑点。任何去成本归因都只是账目解释，不能冒充去成本后的重新回测。

随后补齐共享账户回放：复用现有 Rust 成交、账户资金、成本、保护单、出场与风险模块，按所有币种的共同时间轴推进。还原 Demo 的扫描顺序、每轮开仓数、同币冲突及实际入场时点。首先核对订单级执行一致性，再比较组合净收益、组合回撤和资金占用。

禁止按已观察到的盈利币种名单筛选。可交易池只使用当时已知的数据，预先固定少量候选，例如按上一完整 UTC 日成交额排名的前 50/100 个合约及足够上市历史。历史盘口不可获取时，成交额只能作为流动性代理，不能编造历史价差。

## 2. 让 LightGBM 直接学习交易的经济结果

增加成本后收益预测的受控对照，保留当前三分类模型作为基线：

- 输入继续使用当时可用的价格、成交、市场背景与 Chronos 特征。
- 多空两个目标分别来自相同生产成交与出场规则下的成熟交易结果，并明确未成交、未成熟和缺失数据的处理。不能只训练事后成功成交或盈利的交易。
- 使用标准化后的成本后净收益回归，比较必要的稳健损失；只有估计的净收益及其保守余量通过预先规定的门槛才允许开仓。
- 三类 BUY/HOLD/SELL 概率不能直接当作交易胜率套用盈亏平衡公式。
- Chronos 保留为候选价格区间和不确定性特征；继续保留移除 Chronos 的对照。暂不把神经权重微调列为优先项。

LightGBM 原生支持 regression、regression_l1、huber 和 quantile 等目标；目标选择本身需要验证，不能据此预言盈利。[官方参数文档](https://lightgbm.readthedocs.io/en/stable/Parameters.html#core-parameters)

## 3. 修正校准与门槛选择顺序，缩短模型陈旧期

预先冻结少量更新频率和训练长度对照，例如每周更新、近期 60/90 天窗口。保留成熟标签的 48 小时隔离，所有特征与选择只使用当时已知的信息。

逻辑顺序明确为：模型训练/早停 → 独立概率校准 → 独立开仓门槛验证 → 确认与前向评估。不能把确认集重新拿去调门槛，也不能在同一校准样本上反复筛出最优交易收益。需要近期模型时，可预先设计滚动样本外预测用于校准；重训与校准兼容性也必须检验。

先分别验证更新频率、收益目标和执行约束的贡献，再考虑组合。限制尝试数量，记录所有候选和失败结果，避免把多项改动同时加入后无法判断原因。

## 4. 用新数据决定是否进入 Demo

本次 180 天数据和最后 20 天历史保留段均已观察过，后续可以用于研究，但不能再次称为新盲测。下一轮实验先记录方案、代码版本、训练截止和前向起点，再使用方案锁定后产生的新数据评估。

对照至少包括不交易基准、当前策略，以及相同搜索预算下独立优化的 LightGBM 基线。验收关注：扣成本净收益、足够的实际交易覆盖、组合回撤、不同时间窗口的稳定性，以及更高成本假设下的结果。样本相关性和行情覆盖不足时继续观察，不能靠几笔交易宣布有效。

沿用既有资金与仓位风险上限。新候选通过执行核对及新数据验收前，保持当前 Demo 模型和配置不变。
