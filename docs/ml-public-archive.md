# 官方公开归档月度数据

`nofx-ml-archive` 使用 Binance 单独发布的公共数据归档。它直接读取公开下载站及公开目录，不调用交易 REST API、不使用代理或账户密钥，也不执行订单。当前环境交易 REST API 返回 HTTP 451；官方公共归档的独立下载产品已通过真实下载和发布方 SHA-256 校验验证可用。

2026-10-14 已验证 `BTCUSDT-1h-2026-10-13.zip`。此轮默认固定 UTC 截止时间为 2026-10-14 00:00（用户时区 +08 为当日 08:00），训练区间为 2026-09-14 00:00 至 2026-10-14 00:00 UTC，另外保留从 2026-09-03 08:00 UTC 起的 256 小时前置上下文。探测仅查看最近三个完整 UTC 日，找不到近期文件时停止，不自动训练更早月份。

```powershell
cargo run --locked --bin nofx-ml-archive -- --probe
cargo run --locked --bin nofx-ml-archive -- --output-dir data/ml/monthly-archive-20261014 --phase all --concurrency 8
```

也可以依次使用 `--phase candles` 和 `--phase history`。小时 K 线阶段完成后 manifest 的 `train_ready` 为真，预测特征缓存可以开始准备；历史阶段全部尝试完成后才将 `history_complete` 设为真。模型训练读取逐币种的 `training_eligible` 和数据校验和。

公开 S3 目录包含当前及已经停止交易的历史合约。采集器保留所有以 USDT 结尾的候选目录及逐个结果，使用系统相同的币种验证规则。训练只接纳最新已发布 UTC 日完整、内部小时连续、足够提供 256 小时上下文和 12 小时标签的币种。没有最新日文件的候选标记 `unavailable_latest_day`，不将其视为现有可交易币种；目录无法区分已下架和暂时缺少文件。这个范围是最近仍发布有效数据的公共 USD-M 归档市场，不代表全球所有币种，也不能证明当前 REST `TRADING` 状态。

每个可用币种读取已经完成月份的月度 K 线文件及当前月份的逐日文件。例如本轮使用 9 月月度文件和 10 月 1 至 13 日文件，过滤为固定的实际区间。每个 ZIP 和其发布方 `.CHECKSUM` 保存在 `raw/data/futures/um/...`，先验证 SHA-256，再用 Rust ZIP/CSV 库校验 CRC、成员数量、解压大小、表头、数值和闭合小时边界。每个原始 ZIP 最多 32 MiB，CSV 解压总量最多 16 MiB，不在磁盘上展开 ZIP 内部路径。文件经过完整写入和落盘后原子创建，重跑复用并再次校验成功文件。

`symbols/<SYMBOL>.json`、`history/<SYMBOL>.json` 和 `manifest.json` 使用 [月度训练数据模式](ml-monthly-data.md)。小时 K 线包括 OHLCV、成交额、成交次数和主动买入量。缺少历史前缀的币种记录实际首小时、`missing_prefix_hours` 及来源缺失，不能凭目录断言是新上市；其训练样本从可用上下文之后开始。存在内部或末端缺口时排除训练。

历史阶段先发现公开日度/月度目录实际提供的类别，再采集：

- `metrics` 日度归档的全部 5 分钟原始记录保留于 ZIP；训练表选取整点记录，转换为持仓量、全市场及大户多空比、主动成交比。
- `fundingRate` 月度归档中的历史结算事件按结算时刻加入。当前月份尚未发布且没有日度类别时，明确记录该月份缺失。
- 标记价、指数价和溢价小时归档仅在对应类别实际公开时读取。
- 基差、未公开类别、主动买卖量的缺失字段以及历史首次接收时间均明确保留为缺失，不制造替代数值。

资金费率的 `available_at_ms` 为结算时刻，其余历史数据为源时间戳加一小时，与在线推理采用相同保守规则。归档不提供历史实际发布/网络接收时间；没有最新新闻、当前盘口或当前快照回填过去的样本。

`history_complete` 表示历史阶段每个合格币种均已尝试完成；`history_all_available` 表示全部所需历史来源均成功。任何候选主数据或辅助来源错误都会使最终状态为 `complete_with_errors`，真实错误及覆盖率在 manifest 和历史文件中保留。

归档的格式、发布安排与校验文件见 [Binance 官方公共数据说明](https://github.com/binance/binance-public-data)。归档可能被发布方修订，因此每轮冻结原始 ZIP、校验文件、来源地址及内容校验和，而不是依赖将来再次下载的同名文件。
