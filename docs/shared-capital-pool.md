# 交易模拟：统一资金池

## 金额与收益

- 资金池初始金额只读取本地设置；实盘、模拟盘与本地策略共用该资金池。
- 已绑定订单的成交金额、手续费和收益按币安实盘、币安模拟盘、本地策略的顺序选择可用数据。同一笔策略订单的镜像成交不重复计入收益。
- 买入金额按成交数量与成交价格计算；持仓金额按剩余数量与平均入场价格计算。保证金为该金额除以杠杆。
- 已实现收益使用实际成交的已实现盈亏，扣手续费、加有符号的资金费。交易所合并平仓与币种资金费按当时剩余数量分摊给策略订单。
- 本地模型承担没有交易所成交数据的订单计算，保留本地费用模型。
- 总收益 = 已实现收益 + 未实现收益。
- 总权益 = 本地初始金额 + 总收益。
- 可用余额 = 总权益 − 持仓与挂单保证金 − 手续费预留 − 提交中资金占用。
- 手续费预留覆盖待入场单的开仓和平仓手续费（两次），以及当前持仓的平仓手续费（一次）。使用订单成本配置，单次缺省 6 bps。
- 开仓创建和提交执行都检查共享资金池；多个策略的订单创建由数据库事务串行分配资金。限制依据为保证金加手续费，杠杆后名义金额不是总资金上限。
- 新开仓沿用策略配置的单笔仓位比例、最低保证金与单仓风控。同币种的反向开仓被拒绝，防止单向持仓模式下策略互相抵消。

## 存量数据与同步

- 已绑定策略订单读取可取得的成交历史；成交记录持久化并按环境、凭证指纹、币种、成交 ID 去重。
- 未绑定的存量仓位在首次接入时记录实际数量，当前浮盈亏计入权益，后续成交和资金费计入收益。历史充值、划转和线上钱包金额不进入资金池。
- 存量订单若历史平仓明细缺失，使用实际持仓快照确认剩余数量，释放已经结束的资金占用；缺失部分不编造平仓价格或收益，列表及资金概览明确标注收益暂为已取得记录的净额。
- 持仓与挂单通常每 10 秒同步，成交收益每 30 秒同步；手动同步、平仓后强制更新成交账本。
- 新成交与持仓暂时不一致时保留资金占用，暂停新开仓。查询失败保留上次成功快照；收益同步超过两分钟时暂停新开仓。
- 不支持将非 USDT 手续费或资金费直接当成 USDT。此类数据返回核算错误，保留上次结果并暂停新增订单。

## 手动操作

- 单笔持仓的平仓按钮处理该融合行包含的所有执行目标；同币种、同方向的多个策略仓位由交易所合并，平仓前界面展示确认说明。
- 撤单只处理待入场余量，已成交部分保留为持仓。
- 全部平仓先暂停新开仓，再撤销待入场订单，重新同步已成交仓位后执行平仓。完成或部分失败后仍暂停开仓，由用户手动恢复。
- 平仓使用交易所实时持仓数量、市场数量过滤器与正确的持仓方向。单向账户使用 reduceOnly；双向账户使用明确的 positionSide。
- 手动操作与自动化共用持久化执行锁。平仓意图与客户端订单 ID 在发送之前持久化；超时或未知结果先查询原订单，不重复发送。
- 保护单在实际持仓归零后清理；清理失败保留提示并继续对账。未确认平仓成功时不从列表移除实际持仓。

## 接口

- `POST /api/paper/activity/:id/close`：融合持仓平仓或待入场撤单。
- `POST /api/paper/close-all`：全部平仓并撤单，返回各项执行结果。
- `PUT /api/paper/entries-paused`：设置 `{ "paused": false }` 恢复开仓。
- `PUT /api/paper/capital`：设置资金池初始金额。
- `POST /api/paper/exchange-refresh`：强制同步持仓、挂单与成交收益。

所有界面确认由用户触发。开发期间的构建和只读对账不应调用实际下单或平仓接口。
