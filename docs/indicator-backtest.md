# 历史指标与参数组合回测

后端、过滤与回测均为 Rust。策略管理中展开任意策略，新增“免费行情指标 · 历史回放过滤”分组，以及下方“历史指标回测 · 参数组合”入口。

## 数据范围与含义

| 数据 | 历史来源 | 本次接入的参数 |
| --- | --- | --- |
| 持仓数量 OI | Binance `openInterestHist`，REST 最近一个月，5m 统计 | 开关、5/15/60 分钟窗口、数量变化上下限 % |
| 主动成交、VWAP、成交活跃度 | 已收盘 K 线的成交额、主动买入额、成交笔数、成交量 | 开关、同向主动成交占比下限、活跃度下限、价格偏离 VWAP 上限 % |
| 最近已结算资金费率 | Binance `fundingRate` 分页结算历史 | 开关、同向结算费率上下限 % |
| 全市场账户多空比 | Binance 5m 统计，REST 最近 30 天 | 开关、同向比例上下限 |
| 大户持仓多空比 | Binance 5m 统计，REST 最近 30 天 | 开关、同向比例上下限 |
| 20 档盘口 | 本系统实时采集并入库的原始快照 | 开关、同向失衡下限、价差上限 bps |

历史 REST 范围按 [Binance Market Data 官方文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data) 核对。K 线的主动买入字段也包含在 [Binance 官方公开历史数据](https://github.com/binance/binance-public-data) 中。本次补历史使用 REST 分页和 PostgreSQL 本地缓存，统计接口保守使用最近 29 天的范围，并额外读取指标与 K 线预热数据；已落库的数据以后仍可回放。

实时预估下一期费率、结算倒计时和当时的标记/指数价偏离不能直接由已结算费率重建，本次没有把这些实时值用于事后回测过滤。历史盘口百分比深度与实时 20 档快照的口径不同，不能互相替代。区间没有本系统采集的盘口时，开启盘口回测会返回明确错误。

## 参数语义

所有新增过滤开关默认关闭，现有策略继续运行。“指标缺失时禁止入场”默认开启，只影响已开启的过滤项。关闭数据要求时，缺失检查被跳过且单独统计，不补零、不伪造确认。

- OI 使用数量变化；数值 `1` 表示增加 `1%`，不把金额增加当作新增仓位。
- 主动成交占比 `0.55` 表示多头主动买入/空头主动卖出至少 `55%`。
- 成交活跃度是最近 5 根成交笔数 / 前 5 根成交笔数。
- 多头资金费取最近已结算费率，空头取其负值；参数 `0.01` 表示费率 `0.01%`。
- 多头比例取多/空，空头比例取空/多；账户人数和大户持仓是两种独立数据。
- 盘口多头取原失衡，空头取负值。`1 bps = 0.01%`。

在线候选在计划落库与订单提交前应用这些过滤；启用外部指标过滤时会为该候选收集所需数据，不受仅供卡片展示的候选数量限制。已有订单继续读取各自参数快照。

## 使用

1. 展开策略参数，选币种、开始/结束时间（界面为本机时间；结束不含在内）。
2. 点击“补历史数据”，检查每种数据条数和错误。该操作仅请求公共行情并保存历史，不发送交易指令。
3. 将当前参数草稿作为基线，填写参数网格，例如：

```json
{
  "marketFlowEnabled": [false, true],
  "marketFlowMinFraction": [0.5, 0.55, 0.6],
  "marketOiEnabled": [false, true],
  "marketOiWindowMinutes": [15],
  "marketOiMinPct": [0, 0.5]
}
```

4. 点击“运行参数组合回测”。最多 64 个组合、31 天区间及 200 万根×组合；训练与验证分别从初始权益建立隔离账户，共用前置行情预热。
5. 后续验证区间默认 30%。结果只按训练区间的收益百分数减最大回撤百分数排序，至少 5 笔已平仓才标记训练样本充分。点击组合可查看完整参数、数据缺失、风控拦截和成交统计。
6. 对照验证区间的收益、回撤及成交数后，再通过策略管理保存选定参数。回测不会自动修改策略或真实账户。

## 回放和限制

复用 `strategies::analyze`、`market_filters::apply`、`research::normalize_plan`、生产入场置信度/冷却规则、`paper::submit_paper_order`、`paper::advance_paper_order`、`simulator` 和策略保护复核。全局开仓置信度默认门槛为 0.45，连续亏损不再触发熔断。信号只看当时已收盘 K 线，入场最早在后续 K 线，保护修订按原有规则在后续周期生效。

历史统计实际发布时间无法从 REST 还原。本次保守假定统计时间后 5 分钟才可用，结算资金费率后 1 分钟才可用。实时采集按实际获取时间落库；同时满足观测时间和可用时间不晚于决策时间，才允许参与回放。原始数据保存在 PostgreSQL `market_indicator_history`，主键为币种、指标、观测时间、来源，重复采集不会覆盖首次记录。

这是单币种研究回测，不回放全市场选币竞争、交易所历史精度/最小数量变化或实时网络成交延迟。资金费成本继续使用与在线模拟相同的固定成本模型（6 bps 手续费、5 bps 滑点、3 bps/8h 资金费），已结算费率仅作为信号过滤。期末未平仓按共享引擎浮盈计入权益，不强制平仓。报告保留活动订单数、数据断档数、过滤项缺失次数和阻止原因。

接口：`POST /api/research/indicator-history/fetch` 与 `POST /api/research/backtest`。请求公共字段为 `symbol`、`strategyId`、`startTime`、`endTime`，时间支持毫秒或带时区 ISO；回测另接收 `params`、`grid`、`initialBalance` 和 `validationFraction`。两个接口共用研究任务限流，同一时间运行一个。

## 已完成验证（2026-10-08）

发布后的 Rust 服务已通过真实 HTTP 验证，七个策略各暴露 21 个新增参数，六类过滤开关均保持关闭。Demo 自动扫描已恢复，执行状态就绪；时段检查仍为“时段过滤未启用”。

BTCUSDT 区间 `2026-10-07T10:53:00Z`～`2026-10-08T10:53:00Z` 已补齐：含预热 1m K 线 2962 条、15m K 线 299 条、OI/全市场账户多空比/大户持仓多空比各 864 条、结算费率 9 条；公共请求没有错误。回测只加载区间内已收盘辅助 K 线，因此实际使用 15m 298 条。

六组主动成交过滤网格完成按时间拆分的回放，训练分析 1007 次、验证分析 433 次，K 线断档为 0。该策略基线在此区间没有入场信号，不能据此认定任何组合更优。

另用仅存在于隔离请求中的研究参数检查五类可补历史的过滤链路：训练有 185 个原始信号、验证有 87 个；主动成交阈值与 OI 下限变化时，训练过滤数分别为 68/124/131/155，验证为 31/62/58/74，所有指标缺失计数和 K 线断档计数均为 0。剩余候选被共享流动性筛选拦截。该检查没有保存研究参数到在线策略，也没有关闭风控。

完整输入、参数和统计见 [真实接口验证结果](../reports/indicator-backtest-btc-20261008.json)。Rust 格式、全目标检查、Clippy 与 78 项默认测试通过，另有一项独立数据库/HTTP 契约集成验证通过；前端与发布构建通过。独立数据库测试还验证了回测前后模拟账户数据完全一致。
