# 月度全部启用策略研究

入口为 Rust 可执行工具 `nofx-campaign`。启动时读取当前启用策略及其已保存参数，固定最近 30 天区间；默认选择 12 个代表币种：六个主流币、三个成交活跃币及三个高波动币。只使用有足够上市历史的 USDT 永续合约。币种选择使用当前行情，存在存活和选币偏差，研究结果不能代替全市场组合验证。

配置为 `configs/monthly-enabled.campaign.json`。原 `nofx-optimize` 及年度配置保留，不作为本次月度任务入口。

## 启动、状态和停止

```powershell
$env:CARGO_TARGET_DIR = Join-Path (Get-Location) 'target/native-build'
cargo build --release --locked --bin nofx-campaign -j1
$env:PM2_HOME = Join-Path (Get-Location) '.pm2'
pm2 startOrRestart ecosystem.backtest.config.json --update-env
pm2 save
npm run backtest:status
```

仅运行一个小批次，之后可用同样命令续跑：

```powershell
target/native-build/release/nofx-campaign.exe --root . --max-units 1
```

同一个目录只能有一个进程；PM2 运行时第二次启动会被文件锁拒绝。停止使用 `npm run backtest:stop`；再次启动 PM2 后跳过已完成项。也可创建输出目录内的 `STOP` 文件，让独立工具在当前试验结束后退出；恢复前移除该文件。PM2 对正常退出不进行重复拉起。

## 断点与复现

输出位于 `output/monthly-enabled/`，该目录属于本地工件，不进入 Git。准备阶段要求全部币种的数据就绪；部分请求失败时保留已完成数据并每五分钟重试，不进入不完整的候选比较：

K 线下载会复用数据库中连续、字段完整且在收盘后更新过的缓存，只补缺口。请求超时不会丢掉已保存分页；`downloads/` 中的 `reusedKlines` 记录各周期复用数量。尚未收盘或缺少主动成交字段的旧缓存会重新获取。

- `manifest.json`：固定时间、币种、启用策略及参数、风控环境、成本和回放版本摘要；没有交易所或模型密钥。
- `data/币种.json`：固定原始 K 线和历史指标。先补齐所有币种，再进行耗时回放，避免统计 REST 留存窗口继续缩短。
- `downloads/币种.json` 与 `errors/币种.json`：数据来源计数和请求错误。
- `parameters/候选-策略.json`：该候选在全部币种上使用的同一份参数。
- `trials/候选-策略-币种.json`：一个已完成的训练/验证试验。每项完成立即同步落盘并原子替换。
- `status.json`：进程、阶段、当前试验与更新时间。
- `summary.json`：完成进度、各策略基线、候选排名、成交样本及验证改善标记。
- `holdout-策略.json`：该策略的搜索完成后，最佳候选在最终测试区间的结果；无合格候选时写明跳过原因。

异常中断最多损失正在计算的一项；数据、参数和已完成试验都会保留。脚本重启不重新抽取已保存候选，也不重算已完成文件。风控环境或回放版本变化时，工具拒绝混用旧结果；应改用新的 `--output` 目录保存新研究。扩大币种范围同样使用新目录，保留原研究及其最终测试结果。

## 搜索与指标

时间按顺序拆为 60% 训练、20% 验证、20% 最终测试。搜索开始先评估所有策略的现有参数；后续候选搜索原有指标周期和部分入场/出场阈值，以及 OI、主动成交、VWAP、活跃度、已结算费率、全市场账户多空比、大户持仓多空比过滤。默认每个策略 64 个候选（含基线），12 币种、7 策略共 5376 个训练/验证试验。

所有币种的候选参数保持相同。每币种从相同初始权益独立回放，收益等权汇总；报告中的 `maxDrawdownPct` 为最差币种回撤，不是合并资金池的回撤。训练至少 10 笔、验证至少 5 笔、训练至少 3 个币种有成交且没有 K 线断档，候选才参与可靠排名。目标为训练收益减回撤，并惩罚验证不稳定；最终测试不参与选参。没有足够成交时保留“样本不足”，不会把零成交当成获胜。

`improvesBaselineOnValidation` 仅表示验证收益优于基线且为正、训练回撤未超配置门槛，仍需检查最终测试。程序不会保存候选到在线策略，也不会触发交易所下单。

## 策略代码修改前后对照

`nofx-replay` 从已有研究目录的 `manifest.json` 和 `data/` 读取冻结参数、历史行情、风控环境与成本，调用共享 `backtest::replay`。它不连接数据库或交易所，也不读取最终测试结果；仅支持 `training` 和 `validation`。代码版本可以不同，输出会同时记录快照版本和本次代码版本，便于检查修复前后的行为。

```powershell
cargo run --release --locked --bin nofx-replay -- --research output/monthly-enabled --symbol SOLUSDT --strategy enhanced-trend-v1 --phase validation --output output/strategy-review/after
```

可重复传入 `--symbol`、`--strategy`。默认回放整个所选分段，`--hours 24` 可限制为分段的最后 24 小时。输出目录必须是新目录；逐项保存参数及结果，不覆盖原有研究文件。对照时应保持币种、分段、时间、参数和成本相同。小样本行为验证不能证明收益改善，观察过的验证区间不能再当作最终测试。

沿用共享 Rust 策略、入场资金约束、冷却、成交成本、分批止盈、移动保护及出场复核。全局开仓置信度默认门槛为 0.45，连续亏损不再触发熔断。杠杆、风险预算和全局风控不进入本次搜索。资金费成本继续使用共享固定模型；历史结算费率作为入场过滤。未平仓按共享账户引擎计入浮盈，不强制期末平仓。

1m 数据覆盖默认要求至少 99%。OI 和多空比 REST 只覆盖最近约一个月，补齐时保守读取最近 29 天；月初不可获取的统计保持缺失，启用相关过滤时禁止入场。统计可用时间保守延后 5 分钟，结算费率延后 1 分钟；不使用未来数据。月度搜索不启用没有完整采集历史的盘口过滤。各项原始信号、缺失、过滤、风控阻止、成交和断档统计保存在试验结果中。

## 持续运行

PM2 的 `nofx-monthly-research` 与 `nofx-api` 分别管理，研究不需要重启 API。工作进程只用一个计算线程串行回放，启动后设为 Windows BelowNormal 优先级。首批搜索完成后守候，数据错误会稍后重试；扩展研究使用新的目录，以免反复用同一测试区间调整参数。

本地 Rust 计算不调用模型，不消耗对话额度；额度影响后续 AI 检查，不会终止已经独立启动的进程。机器应保持开机。关闭 Codex 不影响已启动的 PM2 计算，但本对话的定期检查需要应用运行；断电或重启后可用 PM2 恢复，再从落盘进度继续。

已通过格式、全目标检查、Clippy、90 项默认测试和独立 PostgreSQL/HTTP 集成验证。集成验证额外启动真实 CLI 两次，检查第二次只计算下一项、原结果字节不变、模拟账户不变。
