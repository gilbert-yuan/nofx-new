# Chronos + LightGBM 交易参数搜索

`nofx-ml-optimize` 固定已有 Chronos、预测校准与 LightGBM 模型，搜索信号门槛和保护计划，以共享 Rust 模拟引擎扣成本后的净收益排序。它不读取交易账户、不修改运行配置、不调用交易所下单。

可直接运行 `powershell -File scripts/optimize-ml-model.ps1`；脚本仅构建并调用 Rust 工具，不实现回测业务。再次运行已有目录时使用 `-Resume`。

```powershell
$env:CARGO_BUILD_JOBS='1'
cargo build --release --locked --bin nofx-ml-optimize
.\target\release\nofx-ml-optimize.exe --output-dir output/ml-optimization-20261016

# 同一可执行文件、来源与规则保持不变时恢复已完成的逐币检查点
.\target\release\nofx-ml-optimize.exe --output-dir output/ml-optimization-20261016 --resume
```

默认模型为 `output/ml-monthly-20261014`，数据为 `data/ml/monthly-archive-20261014`，原始预测缓存为其 `feature-cache-v3`。`--symbols BTCUSDT,ETHUSDT` 可作小范围验收；正式结果不应把小范围验收当作全币搜索。模型、源文件、历史辅助指标、原始 Chronos 上下文和缓存指纹均校验；重建69维特征后通过原生 LightGBM DLL取得概率，缓存中的标签、未来收益与旧基础特征向量不参与预测。

搜索前逐币重算原参数的完整旧测试窗口，核对原有概率、样本集合、交易数和净收益。全币核对还要求与原训练报告的19,883条预测、3,449笔平仓及净收益合计相符；任何差异都会停止。原始数据和模型文件不可覆盖。

该复现沿用旧训练器的隐式出场设置。正式候选与当前基线均冻结现已上线的生产出场规则，包含智能均线出场，因此不把旧报告的隐式规则收益冒充当前基线收益。程序默认4个工作线程，只并行独立候选；结果按固定候选顺序聚合，可用`--workers 1`限制资源。

固定48组候选：

| 参数 | 候选 |
| --- | --- |
| 类别概率门槛 | 0.45、0.55、0.65 |
| 第一与第二类别概率差 | 0.05、0.10 |
| ATR14 止损倍数 | 1.5、2 |
| ATR14 止盈倍数 | 4、5 |
| 最大持有小时K线 | 5、11 |

当前基线0.45 / 0.05 / 2 ATR / 5 ATR / 11根包含在候选中。入场带保留参考收盘价±0.5 ATR，所有计划继续通过共享价格关系与成本后盈亏比检查，分批止盈、移动保护和智能退出使用共享规则快照。资金仍是每币独立1,000 USDT，单笔名义最多50 USDT、不超过权益20%、止损预算最多1%，固定1倍杠杆，日损3%、回撤10%；没有通过加大资金或杠杆改善收益。

旧测试窗口按时间分为2026-10-08～10-11开发和10-11～10-14确认。每段统一保留36小时不新开仓的结算尾部，保持12小时成熟标签与因果预热。全部候选先在开发段计算；净收益排名要求完成结算、至少50笔平仓、至少10个有盈亏币种且最大单币回撤不超过10%。选中的参数写入不可覆盖的`selected-policy.json`后，确认段只比较该组和原基线，失败后不会重新选择第二名。两段都盈利、超过基线且不增加最大单币回撤，才标为满足历史盈利升级条件。

不交易的收益0单独列为参照；零交易或证据不足的交易参数不能获选，减亏不能称为实现盈利。报告保留所有候选、费用、滑点、资金成本、逐日结果、币种分布、确认段订单及曲线。滑点已在成交价中反映，不重复扣除。

这里的金额是独立账户结果合计，最大单币回撤不是共享组合回撤。缓存每6小时一条信号，Demo按小时轮转并应用流动性、账户占用和交易所过滤；共享纸面引擎还有1小时入场延迟和24小时待入场期限，Demo会立即路由符合条件的订单并检查首次发送时信号是否小于2小时。它们不构成相同的成交时序。因此历史搜索结果不会自动替换Demo参数。

10月8日至14日历史此前已公开，确认段属于本轮锁定参数后的历史分段复核，不能再称全新盲测。多次在同段历史上择优会产生选择偏差，参见[回测过拟合研究](https://www.davidhbailey.com/dhbpapers/overfitting.pdf)。真正前向验证需要冻结策略后取得足够长的新数据；当前10月14日之后的短窗口扣除结算尾部后不足以证明盈利稳定。

输出目录包括 `run-config.json`、逐币 `preflight/`、全部候选的 `development/`、`selected-policy.json`、详细 `confirmation/`、`report.json` 和 `report.md`。恢复运行绑定实际可执行文件、原生运行库、模型/数据、成本和出场默认值指纹，防止混用不同规则。

主搜索完成后，可用有限方向检查比较“当前默认参数、主搜索选中参数”各自的只多和只空版本，共4个追加候选。工具仅限制允许方向，不反转模型信号；它校验主搜索的来源和逐币预测指纹，仍先冻结开发段选择，再运行确认段。追加候选属于观察历史结果后的探索，不能作为新的盲测。

```powershell
cargo build --release --locked --bin nofx-ml-direction-check
.\target\release\nofx-ml-direction-check.exe --selection-file output/ml-optimization-20261016/selected-policy.json --output-dir output/ml-direction-check-20261016
```

方向工具要求新的输出目录，保留逐币结果、冻结选择、确认详情和来源校验，不修改 Demo 配置。
