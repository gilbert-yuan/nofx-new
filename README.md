# NOFX Web

Vue + Express + PostgreSQL 的 USDT 永续合约研究与交易工作台。公开行情使用 OKX，交易执行使用币安 USDⓈ-M。

使用OKX公开接口，自动获取K线、分析行情、模拟下单和管理止盈止损。

## 页面与职责

| 页面 | 功能 |
| --- | --- |
| 行情工作台 | 币种搜索、K 线、日期定位、价格与 OHLC、单币种及批量 AI 分析 |
| 币安交易 | 连接配置、交易开关、风险限制、持仓复核及执行状态 |
| 模拟交易 | 无限虚拟资金、每 2 小时全量扫描、每笔 100 USDT 保证金、每 5 分钟保护复核及净盈亏账本 |
| 当天总结 | 按日期汇总分析建议 |
| 历史分析 | 按日期和币种查询已保存分析 |
| 策略表现 | 研究信号后续表现统计 |
| 模型设置 | OpenAI 兼容接口、模型、并发数、提示词与默认 K 线周期 |

图表日期选择器使用浏览器本地时间；切换历史图表不改变 AI 分析的最新行情窗口。研究分析与交易执行分别由各自接口和配置控制。

## 启动

先准备 PostgreSQL 数据库，参考 `.env.example` 设置本地 `.env`。不要把实际密钥或数据库密码提交到代码中。

```powershell
npm install
npm run dev
```

前端：http://127.0.0.1:5173；API：http://127.0.0.1:3100/api/health。API 使用 3100 端口以避免本机其他项目占用 3000；已有 .env 也需设置 PORT=3100。自定义 API 端口时同步设置 NOFX_API_TARGET。

Windows 后台运行使用项目内 PM2，避免与上面的开发启动重复运行：

```powershell
npm run pm2:start
npm run pm2:status
npm run pm2:restart
npm run pm2:logs
npm run pm2:stop
```

PM2 配置在 `ecosystem.config.cjs`。网络代理改变后检查该文件中的代理地址并重启。生产静态页面先运行 `npm run build`，再用 `npm start` 启动 API；Express 会提供构建产物。

## 行情同步与交互

- 默认 1 分钟 K 线，每 60 秒尝试同步一次，5 个并发工作器共用行情请求限速。全量同步超过一分钟时跳过重叠任务，下一轮按检查点补齐；实际耗时受币种数量和网络影响。币种列表独立获取，`ALL` 表示 OKX 当前所有活跃的 USDT 永续合约，不保证都在币安上市。
- 首次按配置数量拉取已收盘 K 线；后续从已有检查点或最早缺口向后补齐，重读边界 K 线并去重更新。超过一页会继续分页，失败后保留已提交页面，下次重试接续。
- 每 500 根批量写入数据库，同一页使用事务。交易所缺少数据时报告错误，不伪造 K 线填补缺口。
- 切换币种取消旧的图表请求，图表和历史并行加载；后台状态每 10 秒刷新，同一轮未完成时不会叠加，页面隐藏时暂停轮询。
- 普通请求超时 45 秒，单次分析或持仓复核 3 分钟，批量分析及全量补线等长任务 30 分钟。前端取消或超时不等于后端任务停止；请先查看同步状态或历史记录再重试。
- 自动持仓复核和下单受交易配置约束。单纯研究分析不代表订单已执行，应以交易执行记录和交易所状态为准。

### 行情与交易分离

- 行情域名：`https://www.okx.com`，使用公开 `/api/v5/public/instruments`、`/api/v5/market/candles` 和 `/api/v5/market/history-candles`，无需 OKX Key。最新图表、历史补线、AI 和持仓复核的 K 线均来自此处。
- 交易仍使用币安配置的 Key。账户、持仓、交易规则、执行价格及订单请求仍由币安处理；行情源变更不会消除币安交易接口自身的网络或地区限制。
- 新行情存储为 `OKX_PUBLIC_<symbol>`，旧 `BINANCE_<symbol>` 数据保持原样。检查点按来源隔离，不能把两个交易所的 K 线拼接成连续行情。
- 分析记录冻结 `marketProvider`，策略版本包含行情来源。旧币安分析只读取旧币安数据评估，不以 OKX 后续价格替换。
- OKX 成交量转换为基础币数量。交易端继续按币安实际合约过滤器检查数量和价格步长；同名币种不作倍数映射。币安执行价格与最新已收盘参考价偏差超过 2% 时拒绝自动操作，测试网价差也适用。
- 实现位置：`server/marketData.js`；接口定义参考 [OKX 官方文档](https://www.okx.com/docs-v5/en/)。

### 无 Key 分析与模拟账户

行情和模拟账户完全不使用交易所 Key。工作台“分析方式”可选择自动、本地规则或 AI：自动模式在没有启用模型或没有模型 Key 时使用本地规则，已配置模型时使用 AI；本地规则模式始终不请求模型服务。AI 模式仍需有效模型 Key。

本地规则根据 20/50 根均线和 14 根平均真实波幅生成开仓区间及保护价格；趋势不明确时返回观望，界面标明规则强度而非模型评分。至少需要 50 根已收盘 K 线，建议窗口保留默认 80 根。

自动模拟默认启用本地规则，无需任何 Key；每 2 小时扫描全部当前参考合约，合格的多空计划各投入 100 USDT 保证金，采用推荐的 1～5 倍杠杆。本地计划等待入场最多 6 根、持仓最多 120 根 1m K 线。每 5 分钟重新分析已有持仓，记录保护价格前后变化和理由，只收紧止损，调整从下一根尚未开始的 K 线生效。页面可暂停自动流程、选择 AI 或立即执行一轮。运行时间、进度和任务租约持久保存，重启后接续未完成任务。

也可在“模拟交易”手动选择未过期的有效计划并设置保证金、杠杆及止盈止损。推荐杠杆按止损距离计算，目标止损亏损约不超过保证金的 10%（未计成本，最低 1 倍、最高 5 倍），不是盈利预测。名义仓位 = 保证金 × 杠杆，币数量 = 名义仓位 ÷ 模拟成交价，盈亏只按币数量计算一次。

- 单独的 `simulated_account` PostgreSQL 账本，总模拟资金不设上限，不影响币安余额。每轮合格计划独立下单，允许同币种不同轮次叠加；相同任务与信号重试不会重复下单。累计成交投入为各笔成交保证金之和，已平仓投入收益率为已平仓净盈亏除以已平仓保证金，避免以无限本金计算收益率。
- 从提交之后的未来 K 线开始等待开盘价进入计划区间，避免用提交前的高低价假装成交。过期未入场释放占用资金。
- 后台每 30 秒检查新收盘 K 线，无需打开页面或开启实盘交易。周期内的止盈止损会在该根收盘后计算；同根双触发按止损优先，跳空止损取更差开盘价，缺线冻结检查点等待补齐。
- 每边手续费 0.06%、滑点 0.05%，资金费每 8 小时 0.03% 线性估算。逐仓强平采用固定 0.5% 维持保证金率简化模型，最大扣除该笔保证金和开仓费；不等同于交易所实际强平。手动平仓以最新已收盘参考价结算。
- “策略表现”仍为每条信号独立等名义仓位的研究评估；“模拟交易”记录实际模拟入场、杠杆保证金、保护修改和费用后的收益。

## 目录

- `src/`：当前 Web 前端。
- `server/`：API、行情同步、AI、交易及数据库服务。
- `tests/`：自动化回归与可选数据库集成测试。
- `data/`：本地配置与运行数据；`.pm2/`：进程日志与状态。
- `flutter_app/`、`python_app/`：其他客户端或实现，不参与当前 Web 构建；Vite 已忽略这些目录及运行日志的文件监听。

行情失败先查看工作台同步状态及 PM2 日志；AI 失败查看页面错误、模型接口配置与代理；保存 API Key 时保留已返回的掩码可保持原值，清空输入并保存会移除密钥。模型并发上限为 5。

测试通过表示覆盖场景正常，不代替真实交易所环境验证。交易相关回归应使用模拟客户端或测试网，实盘配置由使用者决定。
